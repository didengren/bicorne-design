# 幻灯片设计规范

> 从 huashu-design 的 slide-decks.md 提取设计知识层，丢弃执行层（HTML 架构、web component、导出脚本）。
> 框架无关——适用于 Keynote、PPT、Google Slides、HTML 幻灯片等任何媒介。

---

## 一、开工前决策

### 交付格式决策树

所有交付都从同一套源文件开始。格式只决定**视觉自由度**和**协作方式**：

```
【永远默认 · 必做】源文件（可在宿主工具中编辑和演示）
   │
   ├── 只要本地演示 / 存档       → 到这里已完成，视觉自由度最大
   │
   ├── 还要 PDF（打印 / 发群 / 存档） → 一键导出，视觉无约束
   │
   └── 还要可编辑格式（同事要改文字）  → 从第一页就按结构化约束写
                                          牺牲渐变 / 复杂装饰 / 特殊排版
```

**混合交付矛盾**：要可编辑格式 + 复杂视觉效果 = 真矛盾。让用户做取舍，不要偷偷降级视觉或增加永续维护债。

### 架构选型

| 维度 | 单文件 | 多文件 |
|------|--------|--------|
| 适用规模 | ≤10 页 | ≥10 页 |
| 并行开发 | ❌ | ✅ 多人/多 agent 零冲突 |
| 样式隔离 | ❌ 全局命名空间 | ✅ 天然隔离 |
| 验证粒度 | 需跳页才能看某页 | 每页独立可验证 |
| 跨页共享状态 | ✅ 简单 | 🟡 需额外机制 |

**默认走多文件**。多文件的作用域隔离和可验证性是单文件补不回来的。

## 二、Showcase-First 工作流

**只要 deck ≥ 5 页，绝对不能从第 1 页直接写到最后一页。**

### 正确顺序

1. 选 **2 个视觉差异最大的页面类型**先做 showcase（如「封面」+「情绪/引用页」）
2. 截图让用户确认 grammar（masthead / 字体 / 色 / 间距 / 结构 / 中英双语比例）
3. 方向通过了再批量推剩下 N-2 页，每页复用已建立的 grammar
4. 全部完成后一起合成 + 导出衍生物

**为什么**：直接写 13 页到底 → 用户说「方向不对」= 返工 13 次。先做 2 页 showcase → 方向错 = 返工 2 次。视觉 grammar 一旦确立，后续 N 页的决策空间大幅收窄。

### Showcase 页选择原则

选视觉结构最不一样的两页。这两页过了 = 其他中间态都能过。

| Deck 类型 | 推荐 showcase 页组合 |
|-----------|---------------------|
| B2B brochure / 产品宣发 | 封面 + 内容页（理念/情感页） |
| 品牌发布 | 封面 + 产品特色页 |
| 数据报告 | 数据大图页 + 分析结论页 |
| 教程课件 | 章节封页 + 具体知识点页 |

## 三、排版体系

### 字号阶梯

幻灯片是给 **10 米外**看的，字要够大。

| 层级 | 字号范围 | 用途 |
|------|---------|------|
| Hero 字 | 180-240px | 封面主标题、封面视觉主角 |
| 标题 | 60-120px | 章节标题、内容页大标题 |
| 副标题 | 26-46px | 英文副标题、章节说明 |
| 正文 | 24-36px（最小 24px，理想 28-36px） | 内容文字、列表 |
| 辅助文字 | 17-21px | 注释、来源标注、页脚 |

### 字重与强调

- **H1 重点词单独上品牌主色**——不要全文堆色，每页 accent 高亮不超过 3 处（过多就失去锚点作用）
- **英文副标题**可用 italic 体增加层次
- **正文 line-height** 建议 1.75-1.85（中文）或 1.4-1.5（英文）

### 背景处理

- 暖米底 `#FAFAFA` + 极淡 radial-gradient noise 增加纸感（非必需，视风格定）
- 纯白底亦可，但大面积纯白在投影环境下容易刺眼

## 四、页面布局模式

一个 deck 里最多用 **4-5 种布局**。多了失去系统性，少了显得单调。

### 7 种常用布局

| 布局 | 结构 | 适用场景 |
|------|------|---------|
| **Title slide** | 纯色背景 + 巨大标题 + 副标题 + 作者/日期 | 封面 |
| **Section divider** | 彩色背景 + 章节号 + 章节标题 | 章节分隔 |
| **Content slide** | 白底 + 标题 + 1-3 bullet points | 文字内容 |
| **Data slide** | 标题 + 大图表/数字 + 简短说明 | 数据展示 |
| **Image slide** | 全出血照片 + 底部小 caption | 视觉冲击 |
| **Quote slide** | 大量留白 + 巨大引语 + 署名 | 情绪页/引文页 |
| **Two-column** | 左右对比（vs / before-after / problem-solution） | 对比展示 |

## 五、视觉节奏

Deck 需要 **intentional variety**——不要每张 slide 长一样，那是模板，不是设计。

### 三维节奏

| 维度 | 节奏策略 |
|------|---------|
| **颜色节奏** | 大部分白底 + 偶尔彩色 section divider + 偶尔 dark 片段 |
| **密度节奏** | 几张 text-heavy + 几张 image-heavy + 几张 quote 留白 |
| **字号节奏** | 正常标题 + 偶尔巨型 hero 文字 |

### 视觉主角轮换

13 页如果全是「文字 + 一张截图」就太单调。**每页的视觉主角类型轮换**：

| 视觉类型 | 适合的 section |
|---------|---------------|
| 封面排版（大字 + masthead + pillar） | 首页 / 篇章封 |
| 单角色 portrait | 介绍单个概念/角色 |
| 多角色合影 / 头像卡并排 | 团队 / 用户案例 |
| 时间轴卡片递进 | 展示「长期关系」「演进」 |
| 知识图谱 / 连接节点图 | 展示「协作」「流动」 |
| Before/After 对比卡 + 中间箭头 | 展示「改变」「差异」 |
| 产品 UI 截图 + 设备框 | 具体功能展示 |
| 大引号 big-quote（半页大字） | 情绪页 / 问题页 / 引文页 |
| 真人头像 + 引言卡（2×2 或 1×4） | 用户见证 / 使用场景 |
| 大字封底 + URL 按钮 | CTA / 结尾 |

## 六、信息密度控制

**新手最容易踩的坑**：把所有能放的信息都塞进一页。

### 核心原则

- **每页控制在「1 个核心信息 + 3-4 个辅助点 + 1 个视觉主角」**，超过就拆到新页
- **少即是多**——观众一页看 10 秒，给他 1 个记忆点比 4 个记忆点更容易记住

### 数据密集页的自审

- 列表/矩阵页：不要把 N 个元素都画成同一大小。用 **主次分层**——5 个主角放大，16 个配角缩小做背景 hint
- 大数字页：数字本身是视觉主角。周围的 caption 不超过 3 行，否则观众眼球来回跳
- 引用页：引语和 attribution 之间要有留白隔开

**自审两条**：数据是不是主角？文字有没有挤在一起？改到留白让你有点不安为止。

## 七、出版物 Grammar 模板

适合 B2B brochure / 产品宣发 / 长报告类 deck。每页复用这套结构 = 视觉完全一致、0 返工。

### 页面骨架

```
┌─ masthead（顶部 strip + 横线）────────────┐
│  [logo] · A Product Brochure      Date · URL │
├──────────────────────────────────────────┤
│                                          │
│  ── kicker（品牌色短横 + uppercase 标签）  │
│  CHAPTER XX · SECTION NAME               │
│                                          │
│  H1（中文衬线 900）                       │
│  重点词单独上品牌主色                      │
│                                          │
│  English subtitle (italic，副标题)        │
│  ─────────── 分隔线 ──────────            │
│                                          │
│  [具体内容：双栏 60/40 / 2x2 grid / 列表] │
│                                          │
├──────────────────────────────────────────┤
│ section name                     XX / total │
└──────────────────────────────────────────┘
```

### Grammar 确认要点

开工前先口头说出你要用的 grammar 系统，让用户确认：

- 背景色：最多 2 种（90% 主色 + 10% 深色 section divider）
- 字型：display 用什么，body 用什么
- 节奏：section divider 用什么视觉处理，普通页用什么底
- 图像：hero slide 用全出血照片，data slide 用 chart

## 八、Speaker Notes

**默认不加**，只在用户明确要求时才加。

### 写作要点

- **完整**：不是提纲，是真要讲的话
- **对话式**：像平时说话，不是书面语
- **长度**：200-400 字最佳
- **情绪线**：标注重音、停顿、强调点

2. [ ] 每一页没有空白页、没有布局错位
3. [ ] 打印预览每页恰好一页且无裁切

5. [ ] 全部页面肉眼过一遍
6. [ ] 搜 `TODO` / `placeholder` 残留，确认都清理了
